## Requirements Summary

From spec.md:

### Timeouts
- **FR-016**: System MUST implement configurable timeouts
  - Idle connection timeout (5 minutes default)
  - Synthesis timeout (30 seconds per sentence)
  - Session initialization timeout (10 seconds)

### Security
- **FR-014**: System SHOULD warn on startup if config file has overly permissive permissions (>0600)
- **FR-008**: System MUST implement reasonable size limits on text chunks (64KB max)

### Observability
- **NFR-005**: All WebSocket connections MUST be logged with session_id correlation
- **NFR-006**: HTTP responses SHOULD include X-Request-ID header for tracing

## Implementation Summary

### Timeouts (FR-016)

All three timeouts implemented in `crates/yappy-server/src/ws.rs`:

1. **Session Init Timeout (10s default)**
   - Added `session_init_timeout_secs` to `ServerConfig`
   - Tracks `connection_start` time at WebSocket connect
   - Sends `session_error` with code `session_init_timeout` and closes connection

2. **Idle Connection Timeout (5 min default)**
   - Added `idle_timeout_secs` to `ServerConfig`
   - Tracks `last_activity` timestamp, updated on every message
   - Logs timeout and closes connection cleanly

3. **Synthesis Timeout (30s default)**
   - Added `synthesis_timeout_secs` to `ServerConfig`
   - New `synthesize_and_stream_with_timeout()` wraps provider calls
   - Sends non-fatal `synthesis_failed` error, continues with next sentence

All timeouts are configurable via `yappy.toml`:
```toml
[server]
idle_timeout_secs = 300
synthesis_timeout_secs = 30
session_init_timeout_secs = 10
```

### Security

1. **Config File Permission Warning (FR-014)**
   - Added `check_config_file_permissions()` in `main.rs`
   - Unix only: warns if permissions > 0600
   - Does not block startup, just logs warning with helpful chmod command

2. **Input Text Size Validation (FR-008)**
   - Added `max_text_size_bytes` to `ServerConfig` (default 64KB)
   - Valid range: 1KB to 1MB
   - Sends non-fatal `message_too_large` error if exceeded

### Observability

1. **Session ID in Tracing Spans (NFR-005)**
   - Added `session_id` field to `ws_connection` span (initially Empty)
   - Records session ID once `session.init` is received
   - All nested logs include the session_id

2. **X-Request-ID Header (NFR-006)**
   - Already implemented via tower-http's `SetRequestIdLayer` and `PropagateHeaderLayer`
   - Generates UUID for each request if not provided

## Decisions Made

1. **Non-fatal timeout errors**: Synthesis timeouts are non-fatal to allow continuing with other sentences, matching the existing error handling pattern.

2. **Unix-only permission check**: Windows permission model differs significantly, so the check is no-op on non-Unix platforms.

3. **Configurable limits with validation**: All new config fields have sensible defaults and validation to prevent misconfiguration.

## Learnings

1. **tracing span fields**: Using `tracing::field::Empty` allows recording span fields later (after session init), which is perfect for the session_id pattern.

2. **Combined timeout checks**: Multiple timeout checks can be efficiently combined in a single `tokio::select!` loop by calculating minimum sleep time.
