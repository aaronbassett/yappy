## Decisions Made

1. **Phoneme Tokenization**: Implemented placeholder ASCII tokenizer for MVP. Production quality would need proper G2P (grapheme-to-phoneme) conversion using espeak-ng or trained model.

2. **Voice Embeddings Format**: Voices-v1.0.bin contains 512 embeddings per voice (one per token length) with 256 dimensions each.

3. **Audio Chunk Size**: Using 20ms chunks (480 samples at 24kHz) for streaming - good balance of latency vs overhead.

4. **ONNX Session Mutability**: `ort::Session::run()` requires `&mut self`, so inference uses write lock which serializes concurrent requests. This is acceptable for MVP.

5. **Mock Provider Pattern**: Created MockTtsProvider for integration tests to avoid requiring actual model download.

## Challenges Encountered

1. **ort API Changes**: The ort 2.0.0-rc.11 API uses `Session::builder()` pattern and `ort::session::Session` path (not directly `ort::Session`).

2. **Concurrent Modification**: File modification during edits required re-reading before edits. This is normal behavior with external linters/formatters.

## Learnings

1. **Streaming TTS Architecture**: Sentence-based streaming with buffer accumulation works well for natural text-to-speech flow.

2. **Binary Protocol Design**: 12-byte header (sequence, sentence_index, duration_ms) provides sufficient metadata for client-side audio reconstruction.

3. **Test Server Pattern**: Using `TcpListener::bind("127.0.0.1:0")` with random port for integration tests is clean and reliable.
