## Requirements Summary

From spec.md User Story 6 and contracts/:

### Error Recovery During Streaming

The server must handle non-fatal synthesis errors gracefully, continuing to receive audio for successful sentences while notifying the client of failures.

### Error Classification

**Non-fatal (streaming continues):**
- `synthesis_failed` - TTS provider failed to synthesize a sentence
- `rate_limited` - Provider rate limit hit
- `provider_timeout` - Provider request timed out

**Fatal (connection closes):**
- `protocol_violation` - Malformed messages, wrong sequence
- `internal_error` - Unrecoverable server failures

### Requirements

- **FR-040**: System MUST report non-fatal errors inline without closing the connection
- **FR-041**: System MUST report fatal errors and close the WebSocket connection cleanly
- **FR-042**: Error messages MUST include a code and human-readable message
- **FR-043**: Errors MUST include sentence_index when applicable for client correlation
- **FR-044**: Provider failures MUST NOT crash the server; they should produce session-scoped errors

### Error Message Format

Non-fatal error:
```json
{
  "type": "error",
  "code": "synthesis_failed",
  "message": "Failed to synthesize sentence 3: provider timeout",
  "fatal": false,
  "sentence_index": 3
}
```

Fatal error:
```json
{
  "type": "session.error",
  "code": "protocol_violation",
  "message": "Invalid message sequence"
}
```

The error handling was built during Phase 3 (US1 - Basic TTS):

- `is_fatal()` method for error classification

## Decisions Made

1. **Test-focused phase**: Since the implementation was already complete, this phase focused on comprehensive integration testing to verify behavior.

2. **MockSynthesisMode::RateLimited**: Added a new mock mode to test rate-limiting scenarios without changing production code.

## Learnings

1. **Early integration**: Error handling infrastructure was built proactively during Phase 3, which simplified this phase to primarily testing.

2. **Error code pattern**: The `ProviderError::code()` pattern provides a clean way to map internal error types to protocol codes.

3. **Non-fatal continuation**: The `continue` statement in `synthesize_and_stream()` after sending error ensures processing continues for subsequent sentences.
