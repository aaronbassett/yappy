## Requirements Summary

From spec.md User Story 5 and contracts/:

### Audio Format Negotiation

The server must support requesting specific audio formats (Opus/PCM/MP3) during session setup. The server transcodes from the provider's native format when necessary.

### Acceptance Scenarios

1. **Given** a provider that supports multiple output formats, **When** a client requests audio_format "opus" during session init, **Then** session.ready confirms opus codec and audio chunks are Opus-encoded.

2. **Given** a provider that outputs PCM natively, **When** a client requests opus format, **Then** the server transcodes to Opus and delivers audio in the requested format.

3. **Given** a session init requesting an unsupported format for the selected provider, **When** transcoding is not available, **Then** the server responds with session.error explaining the format mismatch.

### Supported Transcoding

- PCM → Opus (using audiopus)
- PCM → MP3 (using mp3lame-encoder)

### Error Codes

- `invalid_format` - When requested format is not available and cannot be transcoded

## Decisions Made

1. **Transcoding module placement**: Created `yappy-core/src/transcode.rs` as the central location for all audio encoding/transcoding logic, making it available to all crates.

2. **Opus encoder configuration**: Used 64 kbps bitrate and 20ms frame size (960 samples at 48kHz) as sensible defaults for voice audio.

3. **MP3 encoder quality**: Implemented configurable quality levels (0-9) with default of 5 for balanced quality/size.

4. **Format negotiation strategy**: Check native support first, then check if provider supports PCM for transcoding. This avoids unnecessary transcoding overhead.

5. **Error messaging**: Invalid format errors include helpful information about available formats and supported transcoding paths.

## Challenges Encountered

1. **LAME MP3 encoder initialization**: Required converting sample rate to i32 for LAME API compatibility.

2. **Opus encoder sample rate validation**: audiopus only supports specific sample rates (8k, 12k, 16k, 24k, 48k). Added validation to prevent runtime panics.

3. **Clippy strictness**: Had to rename similar variable names (`encoder`/`encoded`) and add allows for items_after_statements in test code.

## Learnings

1. **audiopus API**: The audiopus crate provides a clean wrapper over libopus. The `encode` method returns samples, while `encode_to_bytes` returns raw bytes.

2. **mp3lame-encoder**: Simple API but requires explicit buffer sizing based on input samples.

3. **Transcoding capability pattern**: The `TranscodeCapability` enum with `is_available()` method provides a clean way to represent transcoding capabilities.
