## Requirements Summary

From spec.md User Story 9 and related requirements:

### Graceful Shutdown

When the server receives a shutdown signal, it completes in-progress audio synthesis and closes connections cleanly.

### Requirements

- **FR-027**: Providers MUST support cancellation when a client disconnects mid-synthesis. Cancellation shall be cooperative — providers check for cancellation signals and stop work within 5 seconds maximum.
- **SC-007**: Server graceful shutdown completes within 5 seconds, delivering pending audio to active sessions.

### Acceptance Scenarios

1. **Given** active streaming sessions, **When** the server receives SIGTERM, **Then** it stops accepting new connections, completes in-progress audio chunks, sends audio.done to active sessions, and exits cleanly.

### Edge Cases

- What happens when a client disconnects mid-stream? Server should cancel synthesis for that session, releasing resources.

## Implementation Summary

### ShutdownCoordinator (New Module)

Created `crates/yappy-server/src/shutdown.rs` with:

- `ShutdownCoordinator` struct for coordinating graceful shutdown:
  - Tracks active session count with `AtomicUsize`
  - `CancellationToken` for signaling shutdown to all sessions
  - `tokio::sync::Notify` for session drain notification
  - Configurable drain timeout (default 5 seconds)

- `SessionGuard` RAII type:
  - Auto-decrements session count on drop
  - Provides access to child cancellation tokens
  - Supports creating tokens for individual synthesis operations

### Server Startup (main.rs)

Completed the main.rs implementation:

- Calls `register_providers()` to initialize TTS providers
- Creates `ShutdownCoordinator` and integrates with `AppState`
- Sets up signal handlers:
  - SIGTERM via `tokio::signal::unix::signal(SignalKind::terminate())`
  - SIGINT via `tokio::signal::ctrl_c()` (cross-platform)
- Starts server with `axum::serve().with_graceful_shutdown()`
- Waits for session drain with 5-second timeout after shutdown signal

### WebSocket Handler Updates (ws.rs)

- Registers sessions with `ShutdownCoordinator` on connect
- Message loop uses `tokio::select!` to monitor shutdown token
- New `handle_graceful_shutdown()` function:
  - Flushes remaining buffer content
  - Sends `audio.done` to client
  - Closes WebSocket cleanly
- Cancellation tokens propagated to `provider.synthesize()` calls
- Checks cancellation between sentences and during streaming

## Decisions Made

1. **ShutdownCoordinator as separate module**: Kept shutdown coordination logic isolated from other server components for better testability and separation of concerns.

2. **SessionGuard RAII pattern**: Using RAII for session registration ensures sessions are always unregistered, even on panics or early returns.

3. **Child cancellation tokens**: Each session gets a child token from the coordinator's main token, allowing hierarchical cancellation.

4. **Drain notification via Notify**: Used `tokio::sync::Notify` instead of channel for one-shot notification when all sessions complete, avoiding complexity of tracking receivers.

5. **Graceful message loop exit**: Used `tokio::select!` with bias towards normal message processing, checking shutdown only when no messages pending.

## Learnings

1. **tokio::signal on Unix vs Windows**: SIGTERM handling requires `tokio::signal::unix` which is Unix-only. Used `#[cfg(unix)]` to conditionally compile. SIGINT (Ctrl+C) via `ctrl_c()` is cross-platform.

2. **CancellationToken hierarchy**: `tokio_util::sync::CancellationToken` supports parent-child relationships - calling `cancel()` on parent cancels all children, which is ideal for coordinated shutdown.

3. **axum graceful shutdown**: `axum::serve().with_graceful_shutdown()` stops accepting new connections when the future completes, but existing connections continue until they close. Need explicit coordination for session draining.

4. **Test server design**: Integration tests needed a specialized `ShutdownTestServer` that exposes the `ShutdownCoordinator` for programmatic control, rather than relying on OS signals.
