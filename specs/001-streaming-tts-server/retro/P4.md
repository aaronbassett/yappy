## Decisions Made

1. **Separate tracking for provider initialization vs runtime health**: `provider_statuses` tracks initialization state, while `health_check()` tracks dynamic runtime status. This allows reporting on providers that failed to initialize.

2. **Different JSON shapes for available vs unavailable providers**: Used `#[serde(untagged)]` enum to produce different response structures - available providers include full metadata, unavailable include only status and reason.

3. **Alphabetically sorted provider list**: /providers endpoint returns providers sorted by ID for consistent ordering.

4. **Platform-aware status for AVSpeech**: Reports "unavailable" on non-macOS platforms with clear reason.

## Challenges Encountered

1. **Phase 3 completeness**: Discovered that provider selection and session.error functionality was already fully implemented in Phase 3. Tasks T102-T105 were marked as pre-existing rather than duplicating work.

## Learnings

1. **Initialization vs runtime status distinction**: Important to track both the initial configuration/load status of providers separately from their runtime health status. This enables accurate reporting in /providers and /health endpoints.

2. **Feature-gated dependencies**: Using `#[cfg(feature = "...")]` with optional dependencies keeps the build minimal when providers aren't needed.
