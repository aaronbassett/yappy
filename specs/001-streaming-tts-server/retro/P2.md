## Decisions Made

1. **Message type naming**: Used serde rename for exact protocol match (e.g., "session.init" instead of "session_init")
2. **Provider registry**: Used Arc<dyn TtsProvider> for thread-safe sharing across Axum handlers
3. **Health status logic**: ok (all available) → degraded (some unavailable) → unhealthy (none available)
4. **Config validation**: Added in yappy-core rather than yappy-server for reusability

## Challenges Encountered

1. **Pre-existing code**: Many Phase 2 tasks were already completed in Phase 1. Updated tasks.md to mark them as pre-existing.
2. **Serde tag naming**: WebSocket protocol uses dots in type names (session.init), requiring explicit `#[serde(rename = "session.init")]`

## Learnings

1. Core types provide a solid foundation - the TtsProvider trait is well-designed for streaming
2. The config validation approach catches issues at startup rather than runtime
3. AppState with Arc-wrapped fields enables cheap cloning for Axum handlers
