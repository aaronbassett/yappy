## Requirements Summary

From spec.md User Story 7 and contracts/:

### Sentence Buffer Intelligence

The server must intelligently accumulate and segment text into natural sentences before synthesis, handling edge cases like abbreviations and decimal numbers.

### Requirements

- **FR-010**: System MUST accumulate incoming text chunks and emit complete sentences to the TTS provider.
- **FR-011**: Sentence buffer MUST handle common abbreviations without false sentence breaks (Dr., Mrs., U.S.A., etc.).
- **FR-012**: Sentence buffer MUST handle decimal numbers without false sentence breaks (3.14, 2.5, etc.).
- **FR-013**: Sentence buffer MUST flush on configurable timeout when no sentence boundary is detected.
- **FR-014**: Sentence buffer MUST split overlong text at clause or word boundaries when maximum buffer size is exceeded.
- **FR-015**: System MUST flush remaining buffered text when text.done is received.
- **FR-016a**: Sentence buffer MUST detect and handle fenced code blocks (triple backticks). Default behavior: skip code blocks. Configurable options: read literally, or announce-and-skip.

### Success Criteria

- **SC-008**: Sentence buffer correctly handles 95%+ of the standard abbreviation test set without false splits.

## Implementation Summary

### SRX-Based Sentence Segmentation

Implemented using the `srx` crate (v0.1.4) with embedded SRX 2.0 XML rules. The rules handle:

- **Titles and honorifics**: Mr., Mrs., Ms., Dr., Prof., Jr., Sr.
- **Academic degrees**: Ph.D., M.D., B.A., M.A., B.S., M.S.
- **Geographic abbreviations**: U.S.A., U.S., U.K.
- **Latin abbreviations**: e.g., i.e., etc., vs.
- **Time notation**: a.m., p.m.
- **Corporate suffixes**: Inc., Ltd., Corp.
- **Decimal numbers**: 3.14, 2.5

Key insight: SRX rules only emit sentences when followed by more text, which is correct for streaming TTS - we need to confirm a sentence is complete before synthesizing.

### Flush Timeout Implementation

Added `tokio::select!` in the WebSocket handler to race between:
- Receiving the next WebSocket message
- A sleep for the flush timeout duration (500ms default)

When the timeout fires and buffer has content, the buffer is flushed and audio is synthesized.

### Code Block Detection and Handling

Implemented three modes controlled by `BufferConfig::code_block_mode`:
- **Skip** (default): Remove code block content entirely
- **ReadLiterally**: Pass code block content through as-is
- **AnnounceAndSkip**: Emit "code block." instead of actual content

Handles:
- Language specifiers (```rust)
- Code blocks spanning multiple WebSocket messages
- Unclosed code blocks treated as literal text on flush

### Buffer Overflow Handling

Pre-existing `force_flush()` implementation handles overflow by:
1. First trying to split at clause boundary (comma, semicolon, colon)
2. Falling back to word boundary if no clause punctuation found

## Decisions Made

1. **Embedded SRX rules**: Rather than loading external rule files, we embed the SRX XML directly in the source code for reliability and deployment simplicity.

2. **Streaming-style boundary detection**: SRX rules only detect boundaries when there's following text. This required updating tests to use proper streaming patterns (e.g., "Hello. More text" instead of just "Hello.").

3. **Code block state tracking**: Added `in_code_block`, `code_block_content`, and `pre_fence_text` fields to track partial fences that may span chunk boundaries.

4. **Lazy SRX initialization**: Used `OnceLock` for thread-safe lazy initialization of SRX rules (compatible with MSRV 1.75).

## Learnings

1. **Test pattern for streaming**: All tests must use trailing text after sentences to trigger SRX boundary detection. This is actually correct behavior for streaming TTS.

2. **SRX crate limitations**: The srx crate requires the `serde` and `from_xml` features for parsing XML rules.

3. **Code block complexity**: Handling code blocks that span multiple chunks requires careful state management and handling of partial fence sequences (e.g., ` ` ` split across pushes).

4. **Session configuration flow**: Code block mode is configured at session initialization via `Session::with_buffer_config()`, passing through from the WebSocket handler.
